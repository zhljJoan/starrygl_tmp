# Flickr W=3 corrected smoothing evaluation

GConvGRU, node regression for next-snapshot log(1+in-degree), converted Flickr dataset and original fixed node/edge ownership. Two A40 GPUs (0/1), three sequential arms, seed 42, hidden 8, Adam 0.001, 100 epochs each, validation at epoch 1/every 5/100. Checkpoint selected by actual-policy validation MSE. W=3 full snapshots, unit stride within each split, short prefix windows, history has W output slots + predecessor. Graph/feature access_pipeline enabled; cache hydration stays on main thread.

Arms: exact owner layout with causal per-slot state and synchronous neighbor exchange; bounded shared_hot + cumulative cold increment (no hot blend); same bounded path + learnable hot local/shared fusion. Both bounded arms use local and received histories separately, hot ratio 0.1, cosine threshold 0.3, max_staleness=1 (publisher skip bound, not measured packet age), no artificial delay. Cumulative increments use sum/count for both hot and cold. Hot target version j+1 and cold input target j are audited separately.

Prepared artifacts are reused only after their signatures validate the unchanged data/preprocess/view layouts. Prepare time is excluded. Timing includes read-audit tensor operations, state commits and epoch flush, but excludes epoch reset and epoch-end audit reduction; evaluation includes warm replay. Record training time, CLI wall time, peak allocator memory, per-slot ages and nonzero corrections, gamma gradients, hot publication counts and cold payload bytes. Layerwise profile wall-clock fields measure CPU launch/wait calls and cannot establish GPU communication overlap.

The first pilot was stopped before recording a complete epoch because inspection found exact W>1 reused latest owner state for an older window. The corrected exact path now retains a causal predecessor and exchanges live neighbor states inside every snapshot; full-graph output and gradient parity passed on two ranks for both GConvGRU and DCRNN. Old hot-layout checkpoint exact replay is omitted for W>1. Test MSE in this report always means the actual arm's returned states.

Old W=1 runs remain on GPUs 2/3 while new runs use 0/1; CPU and storage can contend. This is one seed and includes audit overhead. W=1 historical curves are not mixed into this control. DCRNN new full convergence is deferred until GConvGRU review.
